## 任务一：四旋翼动力学模型（Newton–Euler）

### 理论分析（连续动力学）

四旋翼无人机动力学模型基于牛顿-欧拉方程，描述了位置、姿态和转子的耦合动力学特性。

### 数学理论支撑（方程与物理含义）

#### 位置动力学方程
$$\dot{\mathbf{v}} = \mathbf{g} + \frac{1}{m}(\mathbf{T} + \mathbf{F}_{ext} + \mathbf{F}_{drag})$$

其中：
- $\mathbf{g} = [0, 0, -g]^T$：重力加速度
- $\mathbf{T}$：总推力向量（世界坐标系）
- $\mathbf{F}_{ext}$：外部力
- $\mathbf{F}_{drag}$：空气阻力

#### 姿态动力学方程
$$\dot{\mathbf{R}} = \mathbf{R} [\boldsymbol{\omega}]_\times$$

$$\mathbf{J} \dot{\boldsymbol{\omega}} = \boldsymbol{\tau} - [\boldsymbol{\omega}]_\times (\mathbf{J} \boldsymbol{\omega}) + \boldsymbol{\tau}_{ext} + \boldsymbol{\tau}_{damp}$$

其中：
- $\mathbf{R} \in SO(3)$：旋转矩阵
- $[\boldsymbol{\omega}]_\times$：角速度反对称矩阵
- $\mathbf{J}$：转动惯量矩阵
- $\boldsymbol{\tau}$：力矩向量
- $[\boldsymbol{\omega}]_\times (\mathbf{J} \boldsymbol{\omega})$：科里奥利力矩

### 代码架构图（实现映射）

```
Quadrotor::operator()
├── 状态提取 (位置、速度、姿态、角速度)
├── 中间变量计算
│   ├── 电机转速处理
│   ├── 推力计算 T = k_f * ω²
│   ├── 力矩计算 τ = k_m * ω²
│   ├── 空气阻力计算
│   └── 姿态矩阵正交化
├── 位置动力学
│   ├── x_dot = v
│   └── v_dot = g + (T + F_ext + F_drag)/m
├── 姿态动力学
│   ├── R_dot = R * [ω]×
│   └── ω_dot = J⁻¹(τ - [ω]×(Jω) + τ_ext + τ_damp)
└── 状态更新
```

### 关键代码实现

```cpp
// 位置动力学
x_dot = cur_state.v;
v_dot = gravity + (thrust_world + external_force_ + drag_world) / mass_;

// 姿态动力学
R_dot = R * omega_vee;
omega_dot = J_.inverse() * (moments - coriolis + external_moment_ + tau_damp);
```

## 任务二与任务四：前端规划算法体系（重点：`Astar_searcher.cpp`）

> 本节将“任务二（A*补全）”与“任务四（附加改进）”合并叙述：任务二给出基础 A*；任务四在其上做**体系化增强**。本作业的规划核心实现为 `MRPC-2025-homework/code/src/trajectory_generator/src/Astar_searcher.cpp`，其设计目标并非只求最短路，而是对齐评分函数，在“0 碰撞”的硬约束下尽量降低 RMSE、时间与长度。

### 0. 评分函数驱动的规划目标（为什么不是“纯最短路”）

评分函数为：

\[
\text{Score} = 200\,\text{RMSE} + 0.2\,T + 0.2\,L + 40\,\mathbb{I}_{collision}
\]

其中 RMSE 是**全程轨迹跟踪误差**。因此规划器必须显式考虑：

- **安全性**：路径/轨迹要有足够 clearance，避免碰撞或“贴障导致追踪误差触障”
- **可控性**：减少不必要拐点与垂向抖动，降低控制需求，抑制 RMSE
- **可执行性**：避免中间点过密导致多项式分段数爆炸、系统卡顿与重规划频繁
- **实时性**：保证在有限时间预算内输出“可继续推进”的路径（而不是倒飞/卡死）

为此我们构建了一个分层体系：

```
局部栅格化（set_barrier + hard/soft clearance + 距离场）
    ↓
图搜索（Weighted A* + Theta* any-angle + 角度/高度/清障代价）
    ↓
路径后处理（严格安全 pathSimplify：LoS 裁剪 + 圆角 + 自适应分段 + detour）
    ↓
轨迹级安全校验（safeCheck：更密采样 + min_clearance）
```

- **节点网格**：`Map_Node[i][j][k]`（预分配节点，避免频繁 new）

### 2. 连续空间到栅格图搜索的数学建模

#### 2.1 栅格化与坐标映射

给定地图边界 \([\mathbf{l},\mathbf{u})\) 与分辨率 \(r\)，构造栅格集合：

\[
\mathcal{G}=\{(i,j,k)\mid 0\le i < N_x,\ 0\le j < N_y,\ 0\le k < N_z\}
\]

坐标映射（与实现一致）：

\[
(i,j,k)=\left(\left\lfloor\frac{x-l_x}{r}\right\rfloor,\left\lfloor\frac{y-l_y}{r}\right\rfloor,\left\lfloor\frac{z-l_z}{r}\right\rfloor\right)
\]

\[
\mathbf{p}(i,j,k)=\left(l_x+(i+\tfrac12)r,\ l_y+(j+\tfrac12)r,\ l_z+(k+\tfrac12)r\right)
\]

#### 2.2 状态转移与 26 邻域代价

邻域移动：

\[
s' = s + (\Delta i,\Delta j,\Delta k),\quad \Delta\in\{-1,0,1\}^3\setminus\{0\}
\]

基础边代价：

\[
c_{base}(s,s')=\sqrt{\Delta i^2+\Delta j^2+\Delta k^2}
\]

但纯 \(c_{base}\) 只对应“最短几何距离”，无法反映“可控性与安全性”，因此我们进一步塑形 \(g\) 的增量。

### 3. 安全建模：Occupancy + hard/soft clearance + 距离场

#### 3.1 Occupancy 与点云膨胀（set_barrier）

`data_raw` 记录原始占据栅格，`data` 记录膨胀占据栅格。膨胀可视为对障碍集合做 Minkowski 和（离散近似）：

\[
\mathcal{O}_{infl}=\mathcal{O}\oplus \mathcal{B}(r_{xy},r_z)
\]

其中 \(r_{xy}, r_z\) 来自 `margin` 与 `astar_inflation_*`。实现中把参数读取做了静态缓存（避免点云循环访问参数服务器导致卡顿）。

#### 3.2 hard-clearance：作为“可行性约束”的硬裕度

hard-clearance 半径为 \((R_{xy},R_z)\)（单位：栅格）。定义：

\[
\text{tooClose}(s)=1 \iff \exists o\in\mathcal{O},\ \|(s_{xy}-o_{xy})\|_2\le R_{xy},\ |s_z-o_z|\le R_z
\]

除了目标栅格（允许贴近，但不能占据）外，路径中间点必须满足 `!occ && !tooClose`。

#### 3.3 soft-clearance：作为“偏好项”的软裕度

soft-clearance 通过距离场估计最近障碍距离 \(d(s)\)，并引入二次惩罚：

\[
\Psi(d)=
\begin{cases}
\left(\frac{r_{soft}-d}{r_{soft}}\right)^2,& d<r_{soft}\\
0,& d\ge r_{soft}
\end{cases}
\]

soft-clearance 的意义是：**偏好宽通道，但不会把狭缝直接判死**（与 hard-clearance 的二值判定互补）。

#### 3.4 距离场（Distance Field）：L∞ 棋盘距离 BFS + 增量更新（我们相对 reference 的重要创新）

我们构建的是 26 邻域 BFS 的棋盘距离（Chebyshev / \(L_\infty\)）：

\[
d_\infty(s)=\min_{o\in\mathcal{O}} \|s-o\|_\infty = \min_o \max(|\Delta i|,|\Delta j|,|\Delta k|)
\]

与欧氏距离关系：

\[
d_\infty \le d_2 \le \sqrt{3}\,d_\infty
\]

因此 \(d_\infty\cdot r\) 是欧氏距离的保守下界，用于“安全阈值判定”更稳健。更关键的是：

- **全量初始化**：以所有 occupied cell 为源点 BFS，得到整图距离场
- **增量更新**：在 `map/accumulate=true`（障碍单调新增）时，仅对 `pending_obs_addr_` 触发局部扩散，复杂度接近新增障碍局部范围，极大提升实时性

### 4. 图搜索核心：Weighted A* + 多项代价塑形 + Theta* any-angle

#### 4.1 f 值与启发式（h）

Weighted A*：

\[
f(s)=g(s)+w\,h(s),\quad w>1
\]

启发式 \(h\) 使用 26 邻域下的 3D 对角线距离（单位：格）：

\[
h(s)=d_1\sqrt{3}+(d_2-d_1)\sqrt{2}+(d_3-d_2)\cdot 1
\]

并乘一个极小 tie-breaker（\(1+10^{-4}\)）打破对称性，加快收敛。

#### 4.2 g 的增量：把“可控性/可执行性/安全性”写进代价（核心创新）

我们把一步的增量代价写成：

\[
\Delta g = c_{step} + \lambda_{soft}\Psi(d) + \lambda_{zdev}|z-z_0| + \lambda_{turn}(1-\cos\theta) + \lambda_{zturn}\big||d_{new,z}|-|d_{prev,z}|\big|
\]

其中：

- \(c_{step}\) 是基础步长；若发生垂向移动（\(\Delta k\ne 0\)），乘以垂向惩罚 \(\eta_z>1\)（减少无意义上/下窜）
- \(d\) 来自距离场（或局部扫描）
- \(\theta\) 是前后两步方向夹角，\((1-\cos\theta)\in[0,2]\) 连续可导，比“常数转角惩罚”更稳定
- \(|z-z_0|\) 抑制高度漂移，减少垂向控制负担
- \(zturn\) 抑制“水平↔垂直”突变带来的 jerk

**理论解释**：轨迹跟踪误差在高曲率/大 jerk 处放大；将转角与垂向变化写入代价可降低控制需求，从而降低 RMSE 与刹停次数（降低时间）。

#### 4.3 successor 生成：禁止 corner cutting + hard-clearance + escape mode（鲁棒性创新）

对角线移动易出现“角点穿越”（离散点不占据但连续空间穿障）。我们对每个邻居强制检查轴向与面对角中间格的占据，必要时也做 clearance 检查，确保存在连续可通行通道。

重规划时起点可能在 hard-clearance 区域内，若完全禁止进入 tooClose 区域，会导致 `openset exhausted/no progress`。因此引入 escape mode：允许在 tooClose 内扩展，但要求离障距离单调增大，从而“爬出危险区”。

#### 4.4 Theta* any-angle：父节点重连（显著减少拐点，降低中间点密度）

对当前节点 \(c\)、其父节点 \(p\)、以及邻居 \(n\)，若存在视线通路：

\[
\text{LoS}(p,n)=1
\Rightarrow
g(n)\leftarrow g(p)+\|\mathbf{p}(n)-\mathbf{p}(p)\|,
\ \text{parent}(n)\leftarrow p
\]

这会显著减少网格折线的拐点数量，提高后端多项式轨迹可行性并降低 RMSE。我们的 LoS 使用 **3D 整数 Bresenham-like** 步进并同时检查占据与 hard-clearance（比 reference 的浮点采样更快且更稳）。

#### 4.5 解析直连（analytic connect）：近终点直线段安全即直接连

当当前节点距离终点小于阈值且整段 `segmentSafe` 时，直接把终点父节点设为当前点，减少终点附近的冗余扩展与拐点。

#### 4.6 超时/开集耗尽时返回“best-so-far 前缀”：保证持续推进（解决倒飞/卡死）

当搜索超时或开集耗尽时，不再使用会导致倒飞的 retreat，而是返回离目标最近的 best-so-far 前缀路径，并标记“未到达终点”。上层状态机持续重规划，保证系统单调向终点推进。

同时通过连续端点锚定（continuous start/goal）保证：**终点逻辑不被破坏，起点不乱跳**。

### 5. 路径后处理 `pathSimplify`：严格安全的简化、圆角、自适应分段与 detour（我们相对 reference 的关键创新）

`pathSimplify` 的核心原则是：**无法证明安全就不插点；必要时回退到更保守的路径**。主要步骤：

1. 去重（de-dup）
2. `segmentSafe` 贪心 LoS 裁剪（中间点必须 hard-safe，端点仅要求 free）
3. 轻量圆角 fillet（只有当三段都安全才插点）
4. 前向锥探测（forward cone probing）估计前方障碍距离，动态选择分段最大长度，避免空旷区过密点
5. strict pushSeg：若一段不安全，优先找 detour（侧向/轻微竖向绕障点），否则递归二分；任一步失败即回退到保守路径

该设计能同时解决：

- **点过密**：导致规划/可视化/轨迹段数爆炸
- **强行插点穿障**：导致碰撞或轨迹安全检测漏检
- **近终点乱跑**：过多拐点与不稳定 yaw 触发抖动

### 6. 轨迹级安全校验 `safeCheck`：更密采样 + min_clearance（解决高速穿障漏检）

对多项式轨迹 \(\mathbf{r}(t)\) 以时间步长 \(\Delta t\) 采样，检查：

- map bounds
- occupancy
- hard-clearance
- 可选 min-clearance（米，折算控制误差裕量）

采样步长与速度上界 \(v_{max}\) 关系：

\[
v_{max}\Delta t \lesssim r_{obs}
\]

因此 \(\Delta t\) 取与分辨率同阶并允许参数调节，可显著降低“高速穿过细障碍但未采样到”的风险。

## 任务三：控制与执行链路（重点：`so3_control`、`traj_server`）

### 理论分析：为何控制需要与规划“协同设计”

本项目的控制并非单一节点，而是：

`trajectory_generator_node`（轨迹/重规划） → `traj_server`（轨迹转 PositionCommand） → `so3_control`（输出 SO3Command） → `so3_quadrotor_simulator`（姿态内环+动力学）

任何一层的“不一致/不鲁棒”都会放大到 RMSE 与碰撞上。因此控制改进必须包括：控制律推导、增益整定、命令发布一致性、急停语义与评测日志对齐。

### 数学理论支撑：加速度 PD + SO(3) 姿态构造

#### 位置（平动）外环：加速度层面的 PD

定义误差：

\[
\mathbf{e}_p=\mathbf{p}_d-\mathbf{p},\quad \mathbf{e}_v=\mathbf{v}_d-\mathbf{v}
\]

采用带前馈的加速度 PD：

\[
\mathbf{a}_{cmd}=\mathbf{a}_d + K_p\mathbf{e}_p + K_v\mathbf{e}_v + g\mathbf{e}_3
\]

输出合力：

\[
\mathbf{F}=m\mathbf{a}_{cmd}
\]

在理想姿态跟踪下，误差动力学满足：

\[
\ddot{\mathbf{e}}_p + K_v\dot{\mathbf{e}}_p + K_p\mathbf{e}_p = \mathbf{0}
\]

若各轴独立（对角增益），单轴为：

\[
\ddot{e}+k_v\dot{e}+k_x e=0
\]

对应二阶系统整定：

\[
k_x=\omega_n^2,\quad k_v=2\zeta\omega_n
\]

例如 `gains_hummingbird.yaml` 里 \(k_x=25\Rightarrow \omega_n=5\) rad/s，取 \(\zeta\approx1\) 则 \(k_v\approx10\)（临界阻尼附近），解释了“收敛快且不过冲/不过振”的理论依据。

#### 姿态构造（SO(3) 几何）：由 \(\mathbf{a}_{cmd}\) 与 yaw 得到 \(R_d\)

令期望机体系 \(b_3\) 轴与推力方向一致：

\[
\mathbf{b}_{3c}=\frac{\mathbf{a}_{cmd}}{\|\mathbf{a}_{cmd}\|}
\]

令期望机体系 \(b_1\) 轴在水平面内与 yaw 对齐：

\[
\mathbf{b}_{1d}=[\cos\psi_d,\ \sin\psi_d,\ 0]^T
\]

则：

\[
\mathbf{b}_{2c}=\frac{\mathbf{b}_{3c}\times\mathbf{b}_{1d}}{\|\mathbf{b}_{3c}\times\mathbf{b}_{1d}\|},\quad
\mathbf{b}_{1c}=\mathbf{b}_{2c}\times\mathbf{b}_{3c}
\]

最终期望姿态：

\[
R_d=[\mathbf{b}_{1c}\ \mathbf{b}_{2c}\ \mathbf{b}_{3c}]
\]

`SO3Control.cpp` 中对“叉积退化”（\(\mathbf{b}_{3c}\parallel \mathbf{b}_{1d}\)）做了扰动处理，保证数值稳定。

#### 姿态内环（`so3_quadrotor_simulator`）与稳定性要点（理论补充）

本作业的 `so3_control` 输出的是期望姿态 \(R_d\) 与期望合力 \(\mathbf{F}\)。姿态/角速度的闭环主要由仿真器侧姿态控制器完成，典型 SO(3) 几何误差为：

\[
\mathbf{e}_R = \frac{1}{2}\left(R_d^\top R - R^\top R_d\right)^\vee,\quad
\mathbf{e}_\Omega = \boldsymbol\Omega - R^\top R_d \boldsymbol\Omega_d
\]

若采用控制律（概念形式）：

\[
\boldsymbol\tau = -K_R\mathbf{e}_R - K_\Omega\mathbf{e}_\Omega + \boldsymbol\Omega\times J\boldsymbol\Omega
\]

则可用 Lyapunov 函数 \(V=\frac{1}{2}\mathbf{e}_\Omega^\top J\mathbf{e}_\Omega + k_R\Psi(R,R_d)\)（\(\Psi\) 为姿态势函数）证明在合理假设下局部指数稳定。工程上：提高 \(K_R,K_\Omega\) 可加快姿态跟踪、减少急转弯时姿态滞后造成的位置误差，但过大可能引入高频抖动，因此需要与外环 \(K_p,K_v\) 协同整定。

## 实验指标与评分函数（RMSE/时间/长度/碰撞）及理论解释

### 性能指标定义（与脚本严格一致）

- **RMSE**：全程期望位置与实际位置误差的均方根（对所有采样点、三轴一起取平均），不是终点误差
- **飞行时间**：从起点到终点的总飞行时间
- **轨迹长度**：规划轨迹的总长度
- **碰撞检测**：是否发生碰撞（0=安全，1=碰撞）

### 综合评分公式

$$\text{Score} = 200 \cdot \text{RMSE} + 0.2 \cdot \text{Time} + 0.2 \cdot \text{Length} + 40 \cdot \text{Collision}$$

### 理论解释：为什么这些改进会降低 Score？

1. **降低碰撞项**：hard-clearance + 更密的 `safeCheck` + ABORT 真正急停，直接压低 \(40\mathbb{I}_{collision}\)
2. **降低 RMSE**：转角/垂向/高度偏离代价塑形减少高曲率与 jerk；控制外环近临界阻尼整定；避免双发布与 yaw 抖动
3. **降低时间与长度**：Theta* any-angle + analytic connect 减少拐点与冗余扩展；空旷区稀疏分段减少刹停与重规划负担
4. **降低卡顿**：只重置 used_nodes_ + 参数缓存 + 距离场增量更新，降低 CPU 峰值与“规划卡死”概率
